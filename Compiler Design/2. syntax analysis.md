## Top-down parsers
* Grammars suitable for top-down parsing often are harder to design than those used by bottom-up parsers. It is necessary to eliminate left-recursion, We also must left-factor - group productions for the same nonterminal that have a common prefix in the body.
* Top-down parsing attempts to find a leftmost derivation of an input string by recursively expanding the start symbol of the grammar using production rules. This process continues until the input string is derived.
* top-down parsers:
  * 1. Brute force
    2. LL(1): Left-to-right scanning Left-most-derivation (Number of Look-ahead 1). Prequisits: knowledge of first() and follow().
    3. Recursice descent: It used Recuruve procedure(function calls) to parse the input.
   

## Bottom-up parsers:
* Bottom-up parsing, also known as shift-reduce parsing, is sometimes referred to as "reversed rightmost derivation" because Bottom-up parsing works by starting with the input string and gradually reducing it to the start symbol of the grammar. This is achieved by identifying substrings of the input in the right-hand side of production rules and replacing them with the left-hand side non-terminals.
* top-down parsers:
  * 1. Operator precedence: It can parse some ambiguous grammar but not all. the prequsist is that the grammar should be operator grammar meaning, 1. no production rule should have two non-terminals together, 2. grammar have no production rule.
    2. LR(0): Left-to-right scanning Right-most-derivation (Number of Look-ahead 0). Prequisits: knowledge of LR(0) items.
    3. SLR(1): Simple Left-to-right scanning Right-most-derivation (Number of Look-ahead 1). Prequisits: knowledge of LR(0) items.
    4. LALR(1): Look-ahead Left-to-right scanning Right-most-derivation (Number of Look-ahead 1). Prequisits: knowledge of LR(1) items.
    5. CLR(1): Canonical Left-to-right scanning Right-most-derivation (Number of Look-ahead 1). Prequisits: knowledge of LR(1) items.

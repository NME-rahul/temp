# ER modeling

The Entity(genrally refers to tables) Realtionship Diagram explains the realtonship among the entities present in the database. ER model are used to model real-world objets like a person, a car, or a company and the realtion betwen these real-world.In short ER diagram is the structural format of the database.

The ER model specifies enterprise schema that represents the overall logical structure of a database graphically. ER modeling is condidered to be  a top-down approach.

1. **Entity:** An entity may be an object with a physical existence, a particular person, car, house or employee or it may be an object with conceptual existence, a company, a job, a car, or a university course etc.

2. **Entity Set:** An Entity Set of elements of entity type for example, a Entity set of all students of entity type Students.

3. **Relation:**

**Relationship:** A relationship is a asscoiation between two or more etities of same or different entity set. It has no reprresentation in ER diagram as it is an instance or data. In realtion model representes either using a row in a table

5. **Degree:** The number of entitiy set participate in ER diaggram is called degree.

6. **Weak Relationship**: When the primary key of one entity does not contain a primary key component of other entity. or we can say one entity have primary key other one have no primary key.
7. **Weak Entity**: A weak entity doesn't have a primary key so it can't be identified uniquely
